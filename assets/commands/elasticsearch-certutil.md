# TAGLINE

Elasticsearch TLS certificate generator

# TLDR

**Generate a CA** (prompts for output file and password)

```elasticsearch-certutil ca```

**Generate a CA** non-interactively with an empty password

```elasticsearch-certutil ca --out [elastic-stack-ca.p12] --pass ""```

**Generate a node certificate** signed by the CA

```elasticsearch-certutil cert --ca [elastic-stack-ca.p12]```

**Generate a certificate with hostnames and IPs** for verification

```elasticsearch-certutil cert --ca [elastic-stack-ca.p12] --dns [node1.example.com] --ip [192.0.2.1]```

**Generate certificates for many nodes** from a YAML file, in silent mode

```elasticsearch-certutil cert --silent --in [instances.yml] --out [certs.zip] --ca [elastic-stack-ca.p12]```

**Generate CSRs** to be signed by an external CA

```elasticsearch-certutil csr --in [instances.yml] --out [csr-bundle.zip]```

**Interactively generate HTTP layer certificates**

```elasticsearch-certutil http```

**Output in PEM format** (zip file with certificate and key)

```elasticsearch-certutil ca --pem```

# SYNOPSIS

**elasticsearch-certutil** _mode_ [_options_]

# SUBCOMMANDS

**ca**
> Generate a new certificate authority. Produces a PKCS#12 file with the CA certificate and key, or a zip of PEM files with **--pem**.

**cert**
> Generate X.509 certificates and private keys, signed by a CA unless **--self-signed** is given.

**csr**
> Generate certificate signing requests (PKCS#10, PEM) and private keys, packaged in a zip file.

**http**
> Interactive wizard that generates a CA, CSR, or certificates for the Elasticsearch HTTP (REST) interface and Kibana.

# PARAMETERS

**--ca** _file_
> Path to existing CA in PKCS#12 format (cert mode).

**--ca-cert** _file_
> Path to CA certificate in PEM format.

**--ca-key** _file_
> Path to CA private key in PEM format.

**--ca-pass** _password_
> Password for an existing or the generated CA private key (cert mode).

**--ca-dn** _name_
> Distinguished Name of the generated CA (default: **CN=Elastic Certificate Tool Autogenerated CA**).

**--keyusage** _usages_
> Comma-separated key usage restrictions for the generated CA (default: **keyCertSign,cRLSign**, ca mode only).

**--out** _file_
> Output file path.

**--pem**
> Output in PEM format instead of PKCS#12.

**--dns** _names_
> Comma-separated list of DNS names for the certificate.

**--ip** _addresses_
> Comma-separated list of IP addresses for the certificate.

**--name** _name_
> Filename (without extension) for generated certificate.

**--pass** _password_
> Password for the generated private keys. PKCS#12 keys are always protected but the password may be blank (**--pass ""**). PEM keys are only encrypted when **--pass** is given.

**--days** _n_
> Certificate validity period in days (default: **1095**).

**--keysize** _bits_
> RSA key size in bits (default: **2048**).

**--multiple**
> Generate files for multiple instances, prompting for details of each.

**--in** _file_
> YAML file describing the instances (**name**, **ip**, **dns**, **filename**) for silent batch generation.

**--self-signed**
> Create a self-signed certificate (cert mode).

**-E** _key=value_
> Configure a setting.

**-s**, **--silent**
> Minimal output.

**-v**, **--verbose**
> Verbose output.

**-h**, **--help**
> Show all command parameters.

# DESCRIPTION

**elasticsearch-certutil** generates certificates and certificate authorities for securing Elasticsearch clusters. It simplifies the certificate management process by automating the creation of self-signed certificates, certificate authorities, and certificate signing requests.

The tool is essential for enabling TLS/SSL encryption on both the transport layer (node-to-node communication) and the HTTP layer (client API access). It generates certificates in PKCS#12 or PEM format and can include multiple DNS names and IP addresses for cluster deployments.

elasticsearch-certutil streamlines security configuration required for production Elasticsearch deployments and enables features like Elastic Stack security.

# CAVEATS

Usually run from the Elasticsearch home directory as **bin/elasticsearch-certutil**. Only one mode can be given per invocation. Without **--dns** or **--ip**, hostname verification cannot work and **verification_mode** must be relaxed to **certificate**. **--self-signed** is not recommended for securing a cluster. Since Elasticsearch 8.0, a fresh install auto-generates TLS certificates on first start, so the tool is mainly needed for custom or multi-node setups.
