# TAGLINE

npm-generated lockfile pinning the exact installed dependency tree

# TLDR

Note: **package-lock.json** is a generated file, not an executable command. The commands below operate on it.

**Create or update** the lock file based on **package.json**

```npm install```

**Clean install from lock file** (fails if lock file is out of sync; used in CI)

```npm ci```

**Update a specific package** and rewrite the lock file

```npm update [package]```

**Audit** the exact versions in the lock file for known CVEs

```npm audit```

**Inspect changes** to the lock file in a diff

```git diff package-lock.json```

**Update the lock file only**, without touching node_modules

```npm install --package-lock-only```

**Regenerate** the lock file from scratch

```rm package-lock.json && npm install```

# SYNOPSIS

**package-lock.json** - npm dependency lock file (placed in the project root)

# DESCRIPTION

**package-lock.json** is automatically generated by **npm** to describe the exact tree of dependencies that was installed. It records every resolved version, the registry URL, and an integrity hash (SRI), so subsequent installs produce the same **node_modules** regardless of which semver range the manifest allows.

Since npm 7, npm also keeps a hidden lockfile at **node_modules/.package-lock.json** to avoid rescanning the tree; it is only trusted if nothing else modified **node_modules** since.

The file should be committed to version control. In CI, use **npm ci** instead of **npm install**: **npm ci** installs directly from the lock file without touching it, fails fast if it drifts from **package.json**, and is significantly faster.

# KEY FIELDS

```json
{
  "name": "my-project",
  "lockfileVersion": 3,
  "packages": {
    "": { "dependencies": {...} },
    "node_modules/lodash": {
      "version": "4.17.21",
      "resolved": "https://registry.npmjs.org/...",
      "integrity": "sha512-..."
    }
  }
}
```

# LOCK FILE VERSIONS

```
(none) - before npm 5
v1 - npm 5-6
v2 - npm 7-8 (backwards compatible with v1)
v3 - npm 9+ (readable by npm 7+)
```

# CAVEATS

Do not edit by hand. Always commit it to git. Merge conflicts are common and are best resolved by accepting one side and re-running **npm install**. **package-lock.json** is never published to the registry and is ignored in any location other than the root project. Up to npm 11, an **npm-shrinkwrap.json** takes precedence over it; as of **npm 12**, **npm-shrinkwrap.json** is no longer read or written (rename it to **package-lock.json**, the format is identical). Older lockfiles from npm 6 or earlier are upgraded automatically on install.

# HISTORY

Introduced in **npm 5** (2017) to address long-standing reproducibility issues. **lockfileVersion 2** shipped with **npm 7** (backwards compatible with v1), and **lockfileVersion 3** became the default in **npm 9**, dropping the legacy **dependencies** block for a smaller, packages-only format. **npm 12** (2026) retired **npm-shrinkwrap.json** in favor of **package-lock.json**.
